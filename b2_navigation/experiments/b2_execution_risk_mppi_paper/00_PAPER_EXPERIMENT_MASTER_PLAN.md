## 1. 一句话研究问题

在 Unitree B2 的 Nav2 导航链中，MPPI输出的速度还要经过外部速度平滑器和闭源运动控制器。本文研究：

> 这种“计划速度与实际执行速度不一致”是否会在安全关键场景中造成候选轨迹评价错误，以及一种轻量、在线、执行风险感知的 GPU-MPPI 能否在保持 20 Hz 实时性的同时改善安全—效率权衡。

注意：论文不预设答案。若实验表明滚动反馈已经充分消除了影响，本方向应停止，而不是强行声称有效。

---

## 2. 用通俗例子解释问题

假设 B2 离墙不远，MPPI采到一条“向前后马上横移”的候选速度序列。

### 当前理想预测

```text
候选速度
  -> 认为B2立刻达到该速度
  -> 预测能及时横移
  -> 认为离墙还有足够距离
  -> 给这条轨迹较低代价
```

### 真实执行

```text
候选速度
  -> 外部速度平滑器限制加速度
  -> 通信和B2闭源控制器产生响应过程
  -> B2向前速度没有立刻降下来，横向速度也没有立刻升起来
  -> 真实轨迹可能比预测轨迹更靠近墙
```

滚动控制会在下一轮重新计算，但如果下一轮仍然使用同一种错误的未来预测模型，误差还会再次产生。因此要验证的重点不是“有没有误差”，而是：

> 误差是否大到足以改变安全相关候选轨迹的排序和最终导航行为。

## 3. 当前系统的真实控制链

```text
Nav2 Controller Server（20 Hz）
  -> 自定义 MPPIGPUController
  -> /cmd_vel_nav：MPPI原始输出
  -> velocity_smoother（20 Hz，OPEN_LOOP）
  -> /cmd_vel：平滑后的最终速度指令
  -> b2_walk / Unitree SportClient::Move()
  -> B2闭源运动控制器
  -> lf/sportmodestate：位置、速度、偏航速度
  -> /odom 和 TF
  -> 下一轮 Nav2 控制计算
```

当前配置和代码中已经确认：

- 控制频率为 `20 Hz`，控制周期为 `0.05 s`；
- 自定义 GPU-MPPI 为 `8000` 条候选、`H=5`、`dt=0.1 s`；
- 外部速度平滑器为 `20 Hz`、`OPEN_LOOP`；
- GPU-MPPI当前没有使用 Nav2 传入的 `current_vel`；
- GPU rollout 将采样速度直接进行 RK2 位置积分；
- `b2_pub` 当前用电脑接收时刻重写 `/odom` 时间戳，不能直接用该时间戳精确估计端到端延迟。

这些事实说明研究问题存在，但还不能说明它已经产生明显导航危害。

## 4. 论文的候选方法

暂定方法名：**ERAG-MPPI**（Execution-Risk-Aware GPU-MPPI，执行风险感知 GPU-MPPI）。

方法分为四层，必须按顺序实现，不能一开始就上复杂模型。

### 4.1 基础一致性层

- 将预测步长与 20 Hz 控制周期对齐：`dt=0.05 s`；
- 使用 `H=10` 保持总预测时域仍为 `0.5 s`；
- 使用当前实测 `vx、vy、wz` 初始化预测；
- 在候选控制序列内部施加与真实速度平滑器一致的速度、加速度、减速度和死区限制。

这一层属于公平基线修正，不算论文创新。

### 4.2 轻量执行响应层

用每个方向上的离散响应模型预测 B2 的实际速度：

```text
v(k+1) = A * v(k) + B * u(k-d)
```

其中：

- `u`：速度平滑器输出；
- `v`：B2状态反馈速度；
- `d`：离散延迟；
- `A、B`：B2保留旧速度和响应新指令的程度。

先验证固定参数模型；只有当不同方向、速度或地面条件下参数确实变化，才增加在线递推最小二乘更新。

### 4.3 预测残差范围层

根据最近一段时间“预测轨迹—实际轨迹”的残差，估计未来每个时刻可能出现的纵向、横向和角度误差范围。

不把它宣传为绝对安全保证，只称为经过数据校准的经验风险范围。

### 4.4 执行风险门控层

只有当候选轨迹的障碍物净空接近预测误差范围时，才增加风险代价或拒绝该轨迹：

```text
障碍物很远 + 执行误差很小
  -> 保持普通MPPI行为

障碍物很近 + 执行误差可能侵入安全空间
  -> 启用响应感知预测和风险惩罚
```

论文目标不是让所有普通场景都发生变化，而是在安全关键场景中避免错误乐观，同时避免固定大安全距离过度保守。

## 5. 正式研究假设

### H1：真实问题存在

在 B2 的允许运行范围内，理想速度模型在 `0.1–0.5 s` 预测时域上存在可重复、与运动方向相关的轨迹误差。

### H2：误差会影响决策

在停车、墙角、斜向运动或窄通道等安全关键条件下，这种轨迹误差会降低候选轨迹代价排序的准确性。

### H3：固定模型还不够

若执行响应会随方向、速度或运行条件变化，固定响应参数不能一直保持准确，在线更新能够降低多步预测误差。

### H4：方法产生实际收益

在相同安全水平下，ERAG-MPPI比固定保守边界更高效；在相同效率水平下，比理想模型MPPI具有更低的碰撞或近碰撞风险。

### H5：满足实时性

完整方法的控制计算 P99 小于 `50 ms`，能够维持 20 Hz 控制闭环。

## 6. 十个工作日判活/判死实验

这一阶段的目的不是生成漂亮结果，而是决定是否值得继续投入几个月。

### 第1–2天：建立公平基线

在独立实验副本中建立以下控制器：

| 编号 | 控制器 | 作用 |
|---|---|---|
| B0 | 当前自定义GPU-MPPI | 保留现状，说明工程起点 |
| B1 | 时间对齐基线 | `dt=0.05、H=10` |
| B2 | 状态与加速度一致基线 | B1 + 当前速度 + 内部执行约束 |
| B3 | Nav2官方Omni MPPI | 外部参考基线 |

输出：统一配置快照、启动脚本、单场景冒烟结果和控制周期统计。

### 第3–4天：仿真敏感性扫描

在隔离全向底盘中加入可切换的：

- 固定延迟；
- 三轴一阶响应；
- 三轴不同加减速度；
- 外部速度平滑器。

延迟和响应范围此时只用于找敏感区，不作为论文中的B2真实参数。

输出：什么延迟、响应速度、障碍物净空和运行速度组合会使不同模型产生可观察差异。

### 第5–6天：B2安全响应数据

在低速、空旷、有操作员和急停条件下采集：

- 前进、后退；
- 左右横移；
- 原地旋转；
- 斜向运动；
- 加速、恒速、减速和停车。

记录：

- `/cmd_vel_nav`；
- `/cmd_vel`；
- `lf/sportmodestate` 原始时间戳、接收时间、位置和速度；
- 如条件允许，记录外部相机、AprilTag、动捕或独立激光定位。

严禁直接用被重新盖时间戳的 `/odom` 推断精确通信延迟。

输出：三轴阶跃响应、延迟、上升时间、制动距离、拟合参数和留出数据误差。

### 第7–8天：候选排序实验

在空旷区域安全执行一组短速度序列，再在电脑中叠加虚拟墙角、虚拟窄通道和虚拟障碍物。

比较：

- 理想模型预测代价排序；
- 固定响应模型预测代价排序；
- B2真实执行轨迹对应的代价排序。

指标：

- Spearman排序相关系数；
- 预测前10%与真实前10%的重合率；
- 被模型选中轨迹的真实代价；
- 相对于真实最优轨迹的排序遗憾值。

### 第9–10天：做出课题决定

建议内部继续门槛：

1. 理想模型在 `0.5 s` 时域的 P95 位置误差超过 `0.05 m`；
2. 固定响应模型使安全关键候选的排序误差或遗憾值至少下降约 `20%`；
3. 仿真安全场景中至少出现一种具有实际意义的改善：近碰撞率下降、成功率提高，或相同安全率下效率提高；
4. 计算时间仍有希望满足 P99 小于 `50 ms`。

决策规则：

```text
H1不成立 -> 停止响应建模课题
H1成立但H2不成立 -> 误差存在但不影响导航，停止
H2成立但响应参数基本不变 -> 不做在线自适应，重新评估固定模型是否足以成文
H2、H3成立但H4不成立 -> 模型更准但无系统收益，停止
H1–H5均得到支持 -> 进入正式论文实验
```

门槛数值是当前内部决策建议；采集首批真实数据后，应与导师确认并冻结，不能看完最终结果再修改。

## 7. 正式实验矩阵

只有十天门槛通过后才执行本节。

### 7.1 方法对照

| 代号 | 方法 | 回答的问题 |
|---|---|---|
| M0 | 当前GPU-MPPI | 当前项目实际水平如何 |
| M1 | 修正后的理想GPU-MPPI | 改善是否只是修复基础不一致 |
| M2 | 官方Nav2 Omni MPPI | 与成熟公开方法相比如何 |
| M3 | 固定延迟模型 | 一个延迟参数是否已经足够 |
| M4 | 固定完整响应模型 | 固定平滑+响应模型是否足够 |
| M5 | 在线响应模型，无风险范围 | 在线辨识本身有什么作用 |
| M6 | 完整ERAG-MPPI | 风险范围和门控是否带来额外收益 |

### 7.2 场景

#### 普通场景：验证不退化

- 开阔直线；
- 纯横移；
- 斜向到点；
- 大半径90度转弯。

#### 安全关键场景：验证方法价值

- 接近软质墙体后停车；
- 紧凑90度墙角；
- S形障碍；
- 不同宽度窄通道；
- 横移与旋转耦合；
- 在B2允许范围内的不同速度等级。

#### 响应变化场景：验证在线更新必要性

- 不同运动方向；
- 不同速度等级；
- 实验室真实存在的不同地面；
- 只有在厂家和实验室安全规范允许时才测试载荷变化。

人工注入的延迟或响应变化只能称为鲁棒性压力测试，不能冒充B2自然现象。

### 7.3 重复次数

- 仿真：每个主要条件建议至少30个配对随机种子；
- 真机：每个核心条件建议8–10次；
- 各方法运行顺序随机化，避免电量、温度和地面变化只影响某一种方法。

## 8. 评价指标

### 8.1 模型层

- 速度 MAE、RMSE；
- `0.1、0.2、0.3、0.5 s` 多步位置误差；
- P50、P95、最大预测误差；
- 参数随时间、方向和速度的变化；
- 预测误差范围的实际覆盖率。

### 8.2 排序层

- Spearman排序相关系数；
- Top-10%候选重合率；
- 最优轨迹选择一致率；
- 选择遗憾值；
- 因模型不同而改变选择的安全关键控制帧比例。

### 8.3 导航层

- 成功率、碰撞率、近碰撞率；
- 机器人矩形足迹到障碍物的最小净空；
- 停车越界距离；
- 路径横向误差；
- 目标位置和角度误差；
- 完成时间、路径长度；
- 原始与平滑后控制量总变差。

### 8.4 实时性层

- 控制器平均、P95、P99和最大计算时间；
- 超过 `50 ms` 的周期比例；
- GPU是否真实启用；
- CPU、GPU显存和功耗情况（能够稳定采集时再报告）。

### 8.5 统计方法

- 仿真使用相同随机种子的配对比较；
- 连续指标报告中位数、四分位距、均值和95%置信区间；
- 成功率和碰撞率报告样本数与置信区间；
- 同时报告效果大小，不能只报告 `p < 0.05`；
- 所有失败、超时、控制器异常和人工急停均进入统计，不能删除难看的结果。

## 9. 预期论文贡献的合格写法

只有证据完整时，贡献才能写成：

1. 提出一种面向闭源四足运动控制器的轻量执行链模型，显式统一速度平滑、三轴响应和MPPI候选轨迹预测；
2. 提出基于在线执行残差的风险门控机制，仅在执行误差可能侵入障碍安全空间时调整候选轨迹评价；
3. 建立“短指令真实执行 + 虚拟障碍叠加”的候选排序验证方法，直接评价模型误差是否改变MPPI决策；
4. 在隔离仿真与Unitree B2上进行多场景、重复、实时性受控的实验验证。

不能提前写：

- “首次提出”；
- “保证安全”；
- “显著提高导航性能”；
- “适用于所有四足机器人”；
- “达到真实B2最优性能”。
